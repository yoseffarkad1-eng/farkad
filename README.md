# פרקד - רישום עבודה

מערכת לרישום מי עבד היכן, ולהפקת דוח שכר ודוח חיוב ממנו.

**זו אינה מערכת תכנון משמרות.** הסידור נשלח בוואטסאפ, כמו תמיד; האפליקציה עושה
דבר אחד - רושמת מי עבד היכן בפועל. במודל הנתונים עדיין קיימות שתי שכבות
(`plan`/`actual`) לתאימות עם מסמכים ישנים ועם נתיבי הסנכרון, אבל הממשק כותב
וקורא רק את `actual`.

---

**מדריך שימוש בערבית:** [`docs/دليل-الاستخدام.md`](docs/%D8%AF%D9%84%D9%8A%D9%84-%D8%A7%D9%84%D8%A7%D8%B3%D8%AA%D8%AE%D8%AF%D8%A7%D9%85.md) —
מה עושים בפועל בערב ואחרי העבודה, למי שמפעיל את זה ולא כותב אותו.

## הפעלה

אין build ואין התקנה:

```bash
python3 -m http.server 8000
```

**התקנה על המכשיר:** פתח באתר, ובתפריט הדפדפן בחר "הוסף למסך הבית". האפליקציה
נפתחת אז גם בלי חיבור, כי כל הקבצים שמורים במכשיר. עריכה במצב לא מקוון נשמרת
כרגיל ותסונכרן כשהחיבור יחזור.

**באייפון זו לא המלצה.** אתר שנפתח רק ב-Safari מאבד את מה ששמר אחרי שבוע בלי
ביקור. כאן זה אומר שבועיים של רישום שנעלמים בין תשלום לתשלום. אחרי הוספה למסך
הבית הנתונים נשארים. האפליקציה מציגה על כך באנר, ואפשר לסגור אותו לצמיתות.

**עדכון גרסה:** כשיוצאת גרסה חדשה מופיע באנר. היא לא מוחלפת מעצמה - החלפה באמצע
רישום של יום הייתה טוענת מחדש את המסך תוך כדי הקלדה. יש לבמפ את `VERSION`
ב-`sw.js` בכל שינוי בקובץ ששמור ב-cache, אחרת מבקרים חוזרים ימשיכו על הישן.

## מסכים

| מסך | למה הוא |
|---|---|
| **היום** | מסך העבודה. יום אחד, האתרים שפעלו בו, ומי היה בכל אחד. נפתח **לפי אתרים** - כרטיס לאתר עם מי שבו; `לפי עובדים` עובר לרשימה קבועה בסדר הצוות, והבחירה נשמרת. מעל הכול: מה שחסר לחשבון הנוכחי (ימים ריקים, והתראה יומיים לפני הסגירה). |
| **שבוע** | תמונת השבוע והדפסה. לקריאה בלבד - לחיצה על יום פותחת אותו במסך היום. בטלפון הכותרות מתכווצות לאותיות הלוח א׳-ש׳ והתאים לצבע האתר בלבד, כך שכל שבעת הימים נכנסים במסך אחד, עם מקרא מתחת. |
| **עובדים ואתרים** | ניהול הרשימות והגיבוי. |
| **דוחות** | שכר לפי עובד, וחיוב לפי אתר יום ביום, לכל טווח תאריכים. |

## מודל הנתונים

```js
days["2026-08-12"].plan["w_01"]   = { entries: [{ placeId: "p_01" }] }
days["2026-08-12"].actual["w_01"] = { entries: [
    { placeId: "p_01" },                        // רגיל
    { placeId: "p_02", rate: "double" }         // אתר שני, יום כפול
]}
days["2026-08-12"].actual["w_02"] = { absent: true, entries: [] }
```

- **עובד יכול להיות בשני אתרים באותו יום.** זה המצב הרגיל כאן, לא חריג.
- **הסוג יושב על האתר, לא על העובד** - אפשר יום רגיל באתר אחד וכפול באחר.
- **שני אתרים ביום עדיין נספרים כיום עבודה אחד**, אבל כל אתר שומר את הסוג שלו.
- **מוחקים? לא.** עובד או אתר עוברים ל־`active: false`. מחיקה הייתה שוברת ימים
  שכבר חויבו.
- **ארכיון אינו העלמה.** מי שעזב ממשיך להופיע בימים ובשבועות שבהם עבד — מסומן
  "לא פעיל", והרישום שלו נשאר ניתן לעריכה. הוא פשוט אינו חלק מהצוות של היום.

```
js/model/migrate.js הגירה מהגרסה הישנה. לא מנחשת.
js/state.js         מצב יחיד, שמירה, ומעבר גרסה.
js/sync/            סנכרון אופציונלי. כבוי עד שמגדירים Firebase.
js/ui/              מסכים. day.js מצייר את היום; sheet.js משנה אותו.
sw.js               מעטפת לא-מקוונת. בַּמְפּ את VERSION בכל שינוי בקובץ שמור.

```

## הדיאלוגים הם של האפליקציה

אין קריאה אחת ל-`prompt`, `confirm` או `alert` בקוד, וגם אסור שתהיה. בתוך iframe
מבודד — כלומר בכל תצוגה מוטמעת — הדפדפן פשוט מתעלם מהן: הקריאה חוזרת, כלום לא מוצג,
ואין שגיאה. הכפתור "הוסף אתר" נראה אז כאילו הוא לא עושה כלום. במקומן: `askText`,
`askConfirm` ו-`askTell` ב-`js/ui/ask.js`.

אותו דבר לגבי `navigator.serviceWorker`: המאפיין **קיים** ו**זורק** בקריאה בתוך
iframe מבודד, כך שבדיקת `in` עוברת והקריאה עצמה נופלת. בלי try/catch כל מה שבא
אחריה ב-`window.onload` לא רץ.

## העתקה, ומה שהיא לא עושה

כפתור ההעתקה מעתיק מהיום האחרון שיש בו רישום - לא מ"אתמול", שאחרי שבת או חג הוא
ריק - והוא נושא את שם היום שממנו יעתיק (`↧ מיום רביעי 12/08`). הוא ממלא **רק**
עובדים שאין להם שום רישום ביום היעד, ולעולם לא דורס מה שמישהו הקליד ביד — כולל מה
שאחד השניים האחרים הקליד לפני דקה. היעדרות מועתקת רק מהיום הסמוך: היעדרות שהועתקה
מלפני שבוע נראית כמו אמיתית ועולה יום עבודה.

כל פעולה ניתנת לביטול (`js/ui/undo.js`): פס ה"בטל" נעלם אחרי 12 שניות, אבל ה-↶
שבכותרת מחזיק את הצעד האחרון עד שעוזבים את היום - טעות מתגלה בדרך כלל שני שמות
אחרי שהיא נעשתה. הביטול חוזר ליום שבו נעשה השינוי, ולכן מעבר יום מנקה אותו.

עריכה בכמות — העתקה של יום שלם — חייבת לעבור דרך `State.commitMany`. `save()` לבדו
שולח חותמת זמן בלבד; הנתיבים עצמם יוצאים דרך `edit()`. העתקה שדילגה על זה נחתה על
מכשיר אחד ולא הגיעה לאף אחד אחר.

## שני כללים שאסור לשבור

**1. הסקריפטים נשארים קלאסיים.** כל הכפתורים עובדים דרך `onclick` שנפתר בהיקף
הגלובלי. הפיכתם ל־`type="module"` תשבור את כולם בשקט, בלי שגיאה. החריג היחיד הוא
`js/sync/firebase-adapter.js`, כי ה-SDK של Firebase מגיע רק כמודול - והוא מדבר עם
שאר האפליקציה דרך `window`.

**2א. מסמך השרת הוא האמת, לא השעון.** כל כתיבה היא מיזוג ברמת השדה, ולכן המסמך בשרת
כבר מכיל את העבודה של כולם. תמונת מצב נכנסת מאומצת תמיד — היא **אינה** מוכרעת בהשוואת
`updatedAt`, כי החותמות מגיעות משלושה טלפונים שונים, וטלפון ששעונו מקדים בכמה דקות היה
פוסל כל תמונה נכנסת כ"ישנה משלי" ומפסיק בשקט להציג את העבודה של השניים האחרים. עריכות
שעדיין בתור (וגם כאלה שנשלחו ולא אושרו) מוחלות מחדש מעל התמונה שאומצה, ואימוץ נעשה
דרך `State.persist` ולא `State.save` — כדי לא להחתים את העבודה שלהם בשם המכשיר הזה.

**2. אף שינוי לא שולח את כל המסמך.** שלושתכם בונים את הסידור באותו ערב. שליחת
המסמך המלא בכל שמירה פירושה שהשמירה האחרונה מוחקת בשקט את עבודת השניים האחרים.
כל עריכה שולחת נתיב אחד: `days.<תאריך>.<שכבה>.<עובד>`, ומקדמה נוסעת כ-
`advances.<מזהה>` (מחיקה היא null כתוב, לא מפתח שנעלם). חריג אחד: סידור מחדש של
רשימת העובדים שולח את המסמך כולו - לסדר אין נתיב שדה.

## בדיקות

```bash
python3 tests/serve.py 8802 . &
node tests/smoke.mjs
```

השרת חייב להיות מרובה תהליכונים: ה-service worker מוסיף גל בקשות שני על הבקשות
של הדף עצמו, ועם תהליכון אחד הן נתקעות בתור ובדיקה נכשלת מסיבה שאינה קשורה לאפליקציה.

בסביבה בלי playwright מקומי:

```bash
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
CHROME_PATH=/path/to/chrome \
SMOKE_URL=http://127.0.0.1:8802 \
node tests/smoke.mjs
```

## סנכרון

כבוי כברירת מחדל, והאפליקציה עובדת במלואה בלעדיו - הכל נשמר בדפדפן הזה.
להפעלה: `docs/firebase-setup.md`. בתוכנית החינמית, בעלות אפס.

**סנכרון אינו גיבוי.** מחיקה בטעות מסתנכרנת גם היא. שמור קובץ גיבוי מדי פעם.

בנוסף, בכל פתיחה של האפליקציה נשמרת תמונת מצב יומית (שלוש אחרונות) — **לפני** העריכה
הראשונה של אותו יום, כי תמונה שנלקחה תוך כדי עריכה משמרת גם את הטעות. הן מוצגות במסך
"עובדים ואתרים" תחת "חזרה למצב של:".

## חישוב השכר

היחידה היא **היום, לא האתר**. מי שעבר בין שני אתרים באותו יום קיבל יום עבודה אחד -
הנסיעה אינה מזכה בתוספת.

| | |
|---|---|
| יום רגיל | השכר היומי |
| יום כפול | פי שניים מהשכר היומי, בדיוק |
| שעות נוספות | שכר השעה של העובד, לכל שעה, מעל לכל זה |
| יום שבו אתר אחד רגיל ואתר שני כפול | יום כפול |

השכר היומי ושכר השעה נשמרים על העובד, במסך "עובדים ואתרים". שני מצבים שהדוח אומר
במפורש במקום להסתיר:

- **בלי שכר יומי** - הסכום מוצג כמקף, לא כאפס. "לא ידוע כמה" אינו "לא מגיע כלום".
- **שעות נוספות בלי שכר שעה** - הסכום מסומן בכוכבית והשעות אינן נכללות בו.

לחיצה על שם עובד בדוח השכר פותחת את **הימים שלו אחד־אחד**: התאריך, האתרים, יום כפול,
שעות, וכמה יצא לאותו יום. זו התשובה לשאלה "למה הסכום שלי הוא זה", והיא מחושבת באותו
חישוב של הסכום עצמו ולא בדרך שנייה.

שם גם ה**מקדמות**: `+ מקדמה` רושם כסף שניתן באמצע התקופה, והוא יורד מ"נותר לתשלום"
בתחתית - מה שנצבר ומה ששולם מראש הם שני מספרים, ותשלום כפול של הראשון הוא בדיוק
הסיבה שהמקדמות נרשמות. `💬 שלח לעובד` שולח לו את הפירוט כולו בוואטסאפ: הימים, הסכום,
המקדמות, והשורה האחרונה שהיא מה שמקבלים ביד.

## חיוב ללקוח אחד

לכל אתר יש לקוח משלו, ודף שמפרט ארבעה אתרים אינו מסמך שאפשר למסור כמו שהוא. בדוח
החיוב אפשר לבחור אתר אחד: הכותרת נושאת את שמו, מודפסים רק הימים שבהם עבדו בו,
והיצוא ל-Excel הולך אחרי אותה בחירה. בורר האתרים עצמו לא מודפס.

## יצוא

`📊 יצוא` מפיק שלושה גיליונות: **שכר** (סיכום לעובד - נצבר, מקדמות, ולתשלום, אותם
מספרים ואותן כותרות כמו על המסך), **חיוב** (יום ביום, לפי בחירת האתר שעל המסך),
ו**פירוט** — שורה לכל אתר שנעבד בכל יום. הסכום היומי נכתב פעם אחת,
בשורה הראשונה של אותו יום, כדי שסכימה של העמודה תיתן בדיוק את מה שדוח השכר אומר
ולא כפול. בלי אינטרנט הספרייה לא נטענת והכל יוצא כ-CSV.

## הדפסה

`🖨️ הדפסה` בדוחות מדפיס בפריסת A4: בלי תפריטים, שורת כותרות שחוזרת בכל עמוד,
והתקופה מודפסת מתחת לכותרת. **החיוב מתחיל בעמוד חדש** - הוא נמסר ללקוח, ודף השכר
של העובדים לא אמור לנסוע איתו.

במסך צר כל שורה בדוח נפתחת לכרטיס עם התווית לצד כל מספר. בטבלה של שבע עמודות על
מסך של טלפון, מה שנופל מחוץ למסך ב-RTL הוא דווקא הקצה השמאלי - כלומר "לתשלום".
